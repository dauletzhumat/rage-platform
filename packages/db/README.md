# @rage/db

The RAGE Platform database layer. It holds the PostgreSQL schema (Prisma 7), forward-only migrations, seeds and the Prisma client factory used by `apps/api` (and later the workers).

The source of truth for the model is [`docs/SCHEMA.md`](../../docs/SCHEMA.md). The implementation is in [`prisma/schema.prisma`](prisma/schema.prisma), and it also has raw SQL in [`prisma/migrations/*/migration.sql`](prisma/migrations).

## Usage

```ts
import {
  createPrismaClient,
  MatchStatus,
  isSampleSteamId64,
  getDbViolation,
  DB_CONSTRAINTS,
} from '@rage/db';

const prisma = createPrismaClient(); // reads process.env.DATABASE_URL; wires @prisma/adapter-pg
// ... prisma.$disconnect() on shutdown
```

- This is an ESM-only package (`"type": "module"`). Exports resolve to `dist/index.js`, so build it first (`pnpm --filter @rage/db build`; turbo does this through `^build`).
- Never import `src/generated/**` directly. Everything is re-exported: the `PrismaClient` class and type, the `Prisma` namespace, all enums and all model types.
- Prisma 7 needs a driver adapter. `createPrismaClient` strips the Prisma-only `?schema=` URL parameter and passes it to `PrismaPg` as `schema`.
- **Error mapping:** with driver adapters, `meta.target` is **not** set. Postgres details are in `error.meta.driverAdapterError.cause`. A unique violation gives `P2002`. A CHECK violation or a trigger `RAISE` gives `P2039`. Use `getDbViolation(err)` and `isUniqueViolation(err, DB_CONSTRAINTS.x)` instead of parsing errors by hand.
- UUID primary keys are generated by Prisma Client (`uuid(7)`). The database has no default, so raw SQL inserts must supply `id`. `updatedAt` is also client-managed.

## Model overview

- **Identity:** `User` (immutable `steamId64`, `status`, `isSample`), `AuthSession` (token hash only), `SteamProfile`, `PlayerProfile` (nickname, slug), `UserRoleGrant` (role + scope, revocable).
- **Teams:** `TeamApplication` (PENDING → APPROVED/REJECTED/WITHDRAWN; `createdTeamId` is set on approval), `Team`, `TeamMembership` (a history table; active means `leftAt IS NULL`; `invitationId` links the membership to the invitation that produced it), `TeamInvitation`, `TeamStaff`, `TeamAchievement`, `TeamRankingSnapshot` (labelled with the algorithm version).
- **Tournaments:** `Tournament`, `TournamentStage`, `TournamentRegistration`, `TournamentRoster` (versioned; one LOCKED version per registration; `supersedesRosterId` chains substitutions), `TournamentRosterEntry` (SteamID and nickname snapshots), `Bracket`, `BracketSlot` (`nextSlotId`/`nextSlotPosition` for winners, `loserNextSlot*` for double elimination; a match points to its slot through `Match.bracketSlotId`, so the spec's `source_match_id` is not needed).
- **Matches:** `Match` (series: `format`, the `status` state machine, map wins, `version` for optimistic locking), `MatchRoster`, `MatchMap`, `MatchMapPlayer`, `MapVetoAction`, `MatchRound`.
- **Servers:** `GameServer` (`secretRef` only, **no** password columns), `ServerAgent`, `ServerAllocation` (leases), `ServerCommandRequest` (`commandType` is an enum allowlist, and `payload` must be a JSON object of typed params; there is no free-form command text).
- **Events and stats:** `MatchEvent` (raw, append-only), `PlayerMapStat`, `PlayerRoundStat`, `TeamMapStat`, `Demo` (object key only, never the bytes).
- **Infra:** `AuditLog` (append-only), `OutboxEvent`.

## Constraints

### Enforced by the database

| Rule                                                                                               | Mechanism                                                                                  |
| -------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------ |
| SteamID64 unique, 17 digits                                                                        | `users_steam_id64_key`, CHECK `users_steam_id64_format_chk` (also on the snapshot columns) |
| One active membership per user                                                                     | partial unique `team_memberships_one_active_per_user_uniq` (`left_at IS NULL`)             |
| One active captain per team                                                                        | partial unique `team_memberships_one_active_captain_per_team_uniq`                         |
| One PENDING application per applicant; no two pending apps for the same name or slug               | partial uniques on `team_applications`                                                     |
| APPROVED ⇔ `created_team_id` set; an application creates at most one team; REJECTED needs a reason | CHECKs + UNIQUE `created_team_id`                                                          |
| Team name and tag unique case-insensitively; slugs lowercase                                       | `lower(name)`, `lower(tag)` unique indexes; slug CHECK                                     |
| One PENDING invitation per (team, invitee); no self-invite                                         | partial unique + CHECK                                                                     |
| One LOCKED roster per registration; unique user and SteamID per roster                             | partial unique + `UNIQUE(roster_id, user_id)`, `UNIQUE(roster_id, steam_id64_snapshot)`    |
| One registration per (tournament, team)                                                            | UNIQUE                                                                                     |
| Map banned, picked or decided at most once per match                                               | partial unique on `map_veto_actions`                                                       |
| Match teams distinct; winner is a participant; scores ≥ 0                                          | CHECKs on `matches`, `match_maps`                                                          |
| One active allocation per server and per match                                                     | partial uniques (`released_at IS NULL`)                                                    |
| Event dedup                                                                                        | `UNIQUE(source_server_id, external_event_id)`                                              |
| Non-negative stats, headshots ≤ kills, KAST ≤ rounds, CT + T = rounds won                          | CHECKs                                                                                     |
| `audit_logs` and `match_events` append-only                                                        | `BEFORE UPDATE/DELETE/TRUNCATE` triggers                                                   |

The API should match on the constraint names exported as `DB_CONSTRAINTS`. An integration test checks that every exported name exists.

**Append-only escape hatch:** for deliberate maintenance such as retention pruning, run the change in a transaction with `SET LOCAL rage.allow_append_only_maintenance = 'on'`. The trigger guards against accidents only. It is not a security boundary, because the table owner can drop it. M7 hardening should also `REVOKE UPDATE, DELETE, TRUNCATE` from the application role.

### Enforced by services (API), not the database

- Transition legality of the state machines (match, tournament, application, invitation, registration).
- Roster cap (5 starters + 2 substitutes, configurable), eligibility, and the minimum of 5 verified starters.
- Roster entries are immutable after lock. Substitutions create a new roster version (`SUPERSEDED` → `LOCKED`) with an audit row.
- A map winner and a map player's team must be match participants. The series winner must match the map results.
- Invitation expiry (`expires_at`), with a periodic job or a check at accept time.
- Strict SteamID validation before it reaches the database. Note that Postgres `varchar(17)` silently truncates _trailing spaces_ that overflow the length, so `"7656119…0 "` with 18 characters would be stored. Always validate with `isSteamId64Format` and only accept IDs from verified Steam OpenID.
- Concurrency: run approvals, invitation acceptance, allocation and result commits in transactions. The partial unique indexes are the final arbiter, so map `P2002` on them to `409 Conflict`.

## Migrations: forward-only

- Create migrations with `pnpm --filter @rage/db migrate:dev --create-only --name <name>` (this needs a shadow DB, which Prisma creates temporarily). Alternatively, use `prisma migrate diff --from-config-datasource --to-schema prisma/schema.prisma --script`. Review the SQL, add any raw SQL, then apply.
- Prisma does **not** see the partial and expression indexes, CHECKs or triggers, and it does not try to drop them. An integration test asserts an empty `migrate diff` after deploy. Any new raw constraint must go in a migration and be added to this README and to `DB_CONSTRAINTS` if the API maps it.
- Never edit an applied migration. Production uses `migrate:deploy` only. `migrate dev`/`reset` are never run against shared or production databases.
- **Rollback:** there are no down migrations. To undo a change, write a new forward _repair_ migration that reverses it, with data backfill where needed. Prefer expand → migrate → contract: add nullable columns, backfill, switch code, then drop in a later release. If a migration fails half-way, fix the database with `prisma migrate diff ... --script` + `prisma db execute`, then run `prisma migrate resolve --rolled-back <name>` or `--applied <name>`. Take a backup before any destructive step.

## Seeding

- `seed`: production-safe and currently creates nothing. **Bootstrap admin (M1, not implemented):** env `BOOTSTRAP_SUPER_ADMIN_STEAM_ID64`. When that exact SteamID completes a _verified_ Steam login, auth grants `SUPER_ADMIN` (scope GLOBAL) in the login transaction and audits it. Seeds never create admins.
- `seed:sample`: idempotent demo data that can be run repeatedly. It creates 12 users (`sample.kestrel`…), 2 teams (Sample Falcons, Sample Wolves) created through APPROVED applications with a captain + 4 players each, 1 PENDING application (Sample Herons), the "RAGE Sample Cup (demo data)" tournament (REGISTRATION_OPEN, single-elimination, BO1) with 2 approved registrations and locked roster snapshots, and 1 match (`CREATED`, with no scores, maps, events or stats). Every user, team, tournament and match has `is_sample = true`. If it finds an existing _non-sample_ row with the same key, it refuses to modify it.

### Sample SteamID64 range

Sample users use `76561190000000001`…`76561190000000999`. Individual Steam accounts are `76561197960265728 + accountId`, with `accountId ∈ [0, 2³²−1]`. The sample range is below that base, so its implied account ID is negative and no real Steam account can ever have one of these IDs. Helpers: `isSampleSteamId64`, `isIndividualSteamId64`, `sampleSteamId64(n)`, and the `SAMPLE_STEAM_ID64_MIN`/`MAX` bounds. M1 Steam auth must reject sample IDs, and they are never valid logins.
